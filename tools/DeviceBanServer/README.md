# UID 关联主板与人工封禁（实验功能）

启动器与这个服务一起构成可本地验证的原型：用户同意上报后，管理员输入 UID，查看已上报的主板标识，复选封禁或解除。封禁只影响插件注入；启动器改用普通方式启动游戏，不主动结束游戏进程。已经运行的插件不受这次检查影响，限制在下次启动时生效。

## 能查到哪些设备

- 只有使用接入本服务的启动器、同意上报的设备才会产生关联。无法从 UID 查询接入前未上报的其他机器。
- 来源是本机 `BeyondLocal` 目录中的 UID 历史，不是经过官方认证的登录事件；目录可被修改，共用电脑也可能包含多个账号。页面上的时间是首次/最近**上报**时间，不是登录时间。请结合其他证据人工核实。
- 主板序列号在本地规范化并计算完整 SHA-256，格式为 `MB1-` 加 64 位大写十六进制。没有发送原始序列号、CPU、硬盘、BIOS 信息或账号凭证。与开发者授权使用的综合 HWID 不同。
- 空值、常见厂商占位符和全零/全 F 序列号不产生标识。换主板会改变标识，厂商重复序列号仍可能导致关联冲突。
- 单独封禁选中的主板，不自动封禁该 UID 的其他设备，不按 IP 封禁。

## 本地运行

依赖：.NET SDK 8 及 ASP.NET Core 8 运行时。服务没有额外 NuGet 依赖；当前机器已经安装这些依赖。启动器项目自身按 `global.json` 要求 SDK 10，另需现有 Windows SDK 26100 和 Visual Studio 构建工具；这是启动器的构建要求，不是服务新增的依赖。

在仓库根目录执行 PowerShell：

```powershell
$env:DeviceBan__AdminKey = [Convert]::ToHexString([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
$env:DeviceBan__AdminKey
# 复制刚生成的密钥到你自己的安全位置，管理页面查询需要它。
dotnet run --project tools/DeviceBanServer/DeviceBanServer.csproj
```

打开 `http://127.0.0.1:5088/`，在页面输入管理密钥和 UID。密钥仅保留在当前输入框，不写入浏览器存储，也不放到 URL。默认记录位于服务项目的 `data/devices.json`，已从 Git 排除。可用环境变量 `DeviceBan__DataFile` 指定绝对路径。

配置启动器输出目录的 `appsettings.json`：

```json
"DeviceBan": {
  "ServiceUrl": "http://127.0.0.1:5088"
}
```

启动器的源配置默认留空，避免尚未部署服务时改变原有插件行为。首次启用注入时会显示上报内容和服务地址；选择“仅普通启动”不发送关联数据。关闭注入可停止后续上报。更换服务地址需重新同意。

客户端只接受 HTTPS 或本机 HTTP，拒绝跟随重定向。服务已配置但未同意、无法读取主板或接口失败时，仅本次取消注入，正常启动游戏，且不改写原有注入开关。

## 管理操作

1. 用户使用测试启动器并同意检查，建立关联。
2. 输入违规 UID，查询所有保留期内的关联主板。
3. 人工核实后复选目标，填写原因和 1–90 天期限，点击“限制所选设备的插件”。原因会显示给受限用户，可填写申诉联系方式。
4. “解除所选限制”立即生效；“删除所选记录”同时删除该主板的所有 UID 关联及限制，客户端再次上报会重新建立记录。

接口：

| 接口 | 用途 | 权限 |
|---|---|---|
| `POST /api/device/check` | `{motherboardId,uids}` 上报并返回 `{banned,reason,expiresAt}` | 客户端；按来源 IP 限流 |
| `GET /api/admin/devices?uid=...` | 返回该 UID 的关联主板 | `Authorization: Bearer 管理密钥` |
| `POST /api/admin/bans` | `{motherboardIds,banned,reason,durationDays}` 批量限制/解除 | 管理密钥 |
| `DELETE /api/admin/devices/{motherboardId}` | 删除关联及限制 | 管理密钥 |

## 记录与部署边界

关联在最近上报 90 天后过期；查询/检查时清理，后台每小时额外清理一次。单次封禁最长 90 天，到期释放。JSON 文件以临时文件替换方式保存，重启不会丢失；适用于单进程原型，不适合多副本或大量客户端。

对外部署需 HTTPS、受限管理入口和持久存储；管理密钥不能分发到启动器或提交到仓库。反向代理下应配置可信代理和合适的限流策略。服务避免在默认请求日志里记录 UID 查询参数；反向代理和备份需另行设置留存与访问范围。

这是客户端自报关联，不能证明 UID 所有权或真实硬件，也无法阻止修改客户端、伪造报告或绕过启动器。管理页面因此保留人工选择，不自动按 UID 连带处罚。运营者上线前还需明确身份、联系方式、处理依据、保存/删除及申诉规则。主板哈希仍是可关联的设备标识，不代表匿名化。
